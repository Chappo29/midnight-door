# Система сохранения

Прогресс игрока между матчами: гость сохраняется локально, игрок, вошедший в Яндекс, — ещё и в облаке.
Код: [src/platform/save.ts](src/platform/save.ts) (хранилище и синхронизация),
[src/platform/storage.ts](src/platform/storage.ts) (схема `Progress` и её починка),
[src/platform/yandex.ts](src/platform/yandex.ts) (загрузка SDK). Тесты: [tests/save.test.ts](tests/save.test.ts).

## Архитектура

```
Экраны и матч (main.ts)
      │  store.update(p => …) / store.commit()
      ▼
ProgressStore  ── progress в памяти (один объект на всю игру), rev, at
      │
      ├── локально, сразу: KeyValueStorage
      │       Yandex safeStorage → window.localStorage → память
      │
      └── облако, пачкой: CloudSave → player.setData({ save: snapshot }, flush)
              только если player.isAuthorized()
```

- **Один источник правды** — `ProgressStore.progress`. Больше ничего persistent не лежит отдельно:
  звук (`midnight-door-muted`) перенесён внутрь снимка, `player.setStats` не используется.
- Экраны и `GameScene` не знают о хранилищах и SDK. `player.setData` вызывает только `ProgressStore`.
- Меняют прогресс так:
  - `store.update((p) => …, { critical })` — изменить и сохранить;
  - `store.commit({ critical })` — когда изменение уже сделала чистая функция `meta/*`
    (`buyHero`, `claimDaily`, `recordMatchOutcome`, `previewButtons`).
- `KeyValueStorage` — адаптер: `getItem`, `setItem`, `removeItem`. Остальной код не знает, что за ним.

## Схема сохранения

Один снимок, одинаковый локально и в облаке:

```ts
interface SaveSnapshot {
  v: number;         // версия схемы, сейчас 2 (1 — старое сохранение без обёртки)
  rev: number;       // ревизия: +1 на каждое осмысленное изменение
  at: number;        // время последнего изменения, мс
  progress: Progress;
}
```

Локальный ключ — прежний: `midnight-door-progress`. В облаке — ключ `save` в Player Data.

### Что хранится (persistent)

| Поле | Где меняется | Persistent | Где хранится |
|---|---|---|---|
| `tutorial` (`undefined` / `done` / `skipped`) | `finishTutorial`, `resolveTutorialOnBoot` | да | снимок |
| `matches` — завершённые матчи | `recordMatchOutcome` (meta/unlocks.ts) | да | снимок |
| `wins.easy/hard/nightmare` | итоги матча (main.ts) | да | снимок |
| `hints` — показанные подсказки | `onSeen` подсказки | да | снимок |
| `unlocks.pumpkin/trap/workbench/fridge` (`locked → justUnlocked → seen → available`) | `recordMatchOutcome`, `previewButtons`, `markBadgeSeen` | да | снимок |
| `meta.coins` | награда за матч или выход, подарки, покупки | да | снимок |
| `meta.heroes`, `meta.hero` | `buyHero`, `selectHero` | да | снимок |
| `meta.skins`, `meta.skin` | `buySkin`, выбор в магазине | да | снимок |
| `meta.boosters.candy/door/wrench` | `buyBooster`, `spendBoosters` | да | снимок |
| `meta.daily.last/step` | `claimDaily` | да | снимок |
| `meta.tutorialGift` — подарок за обучение выдан | `finishTutorial` | да | снимок |
| `settings.muted` | кнопка звука | да | снимок (раньше `midnight-door-muted`) |
| `rev`, `at`, `v` | `ProgressStore.commit` | да | снимок |

### Что намеренно НЕ хранится

Всё состояние матча: конфеты и пламя, HP двери и призрака, постройки в комнате, позиции героя и
соседей, цель призрака, перезарядки, фаза матча, сид карты, режим духа. Матч после перезагрузки
начинается заново. Не хранится и `lastDifficulty` (сложность для «Попробовать!» после перезагрузки):
это удобство, а не прогресс. После перезагрузки — «Лёгкая», так было и раньше.

Размер: снимок новичка — 462 байта. После миграции реального сохранения — 500 байт.
Со всеми героями и скинами и 30 подсказками — меньше 2 КБ (проверяет тест). Лимит Player Data — 200 КБ.

## Гость

Гость играет сразу: окно входа не открывается ни при запуске, ни после обучения, ни после матча.
Прогресс пишется локально при каждом изменении:

1. в **safeStorage** Яндекса (`await ysdk.getStorage()`), если SDK загрузился. Это «надёжный
   localStorage», его не стирает iOS;
2. иначе — в обычный `window.localStorage`;
3. если недоступно и он (песочница, запрет) — в память: игра работает, но до закрытия вкладки.

## Вошедший в Яндекс

Если при запуске `player.isAuthorized() === true`, облачный снимок читается через
`player.getData(['save'])` **до первого экрана**. После выбора снимка каждое изменение сначала
пишется локально, потом уходит в облако очередью:

- обычное изменение — через 2 с, одной пачкой со всеми соседними (уходит последний снимок);
- важное (`critical`: покупка, итоги или выход из матча, подарок дня, конец обучения) — через 0,3 с и с `flush: true`;
- не чаще одной записи в 5 с: лимит SDK — 100 `setData` за 5 минут;
- уход со страницы (`visibilitychange` → hidden, `pagehide`) — отправить то, что ждёт, сразу и с `flush`.
  Идёт отправка — дослать сразу после неё. Последняя запись ушла без `flush` (лежит в очереди SDK) — дожать её с `flush`;
- после сбоя `setData` повтор идёт не раньше, чем через 5, 10, 20… 60 с, и новые изменения этот срок не сокращают;
- возврат в игру (`visibilitychange` → visible) — перечитать облако не чаще раза в минуту. Если другое устройство
  записало новее, а здесь ничего не ждёт отправки, взять облачный снимок.

`flush: true` не ставится на мелочи: подсказки, метки «Новое!», выбор героя или скина, звук, списание усилителя.

## Запуск

`main.ts → boot()`, пока видна заставка:

```
initYandexSdk()             ≤ 4 с  /sdk.js + YaGames.init(); нет — null
ysdk.getStorage()           ≤ 2,5 с  safeStorage; нет — localStorage — память
читаем локальный снимок      safeStorage + старый localStorage (миграция)
ysdk.getPlayer()            ≤ 2,5 с
authorized → getData        ≤ 4 с   облачный снимок
выбор снимка (целиком) → миграция → запись выбранного локально
только теперь: обучение или меню
```

Меню или обучение не появляются до того, как прогресс загружен. Картины «профиль по умолчанию →
обучение → через секунду пришло облако» не бывает. Облако не ответило за 4 с — игра начинается на
локальном, а облако подключается позже (до 5 повторов раз в 30 с; второе подключение параллельно
не запускается). Если облачный снимок окажется новее, прогресс заменится на месте, и меню
перерисуется (`onReplaced`; в матче — не трогаем, меню возьмёт новое при выходе).

Облако ответило поздно, а на этом устройстве при запуске сохранения не было (новый браузер)? Тогда
облако выигрывает, даже если здесь уже набежали ревизии: пара подсказок в обучении не должна
перетереть настоящую игру (`preferCloudIfFresh`). Действует только для первой попытки при запуске: повторы через 30 с и позже
выбирают по ревизии — к этому времени на устройстве уже может быть настоящая игра. Проигравший локальный снимок кладётся в `…-replaced`.

## Выбор между локальным и облачным

Снимок выбирается **целиком**, поля не сливаются. `Math.max` по монетам вернул бы потраченное на
покупку. Функция `chooseSnapshot`:

| Случай | Итог |
|---|---|
| A: `local.rev > cloud.rev` | локальный; отправляется в облако |
| B: `cloud.rev > local.rev` | облачный; пишется локально |
| C: ревизии равны | новее по `at`; при полном равенстве — локальный, ничего не качаем |
| D: один битый или отсутствует | другой (битое облако перезаписывается локальным) |
| E: оба битые | профиль по умолчанию, в DEV — `console.warn`, игра не падает |

Нечитаемое локальное сохранение перед новым профилем копируется в `midnight-door-progress-corrupt`.
Локальный снимок, проигравший облаку, — в `midnight-door-progress-replaced`. Их можно разобрать
вручную по обращению игрока.

Защиты:

- в облако ничего не пишется, пока облачный снимок не прочитан. Иначе старое устройство при сбое `getData` перетёрло бы свежий облачный прогресс;
- нетронутый профиль по умолчанию (сохранения нет) в облако не отправляется никогда.

## Ревизия

`commit` делает `rev += 1` и `at = max(now, at + 1)`, потом пишет снимок. Чтение, загрузка и
миграция ревизию не меняют. Ревизия продолжается от загруженного снимка: устройство, взявшее
облачную ревизию 50, следующее изменение запишет как 51.

## Миграция

Старое сохранение — это `Progress` в корне JSON, без `v` и `rev`. Разбор (`parseSnapshot`):

1. `normalizeProgress` чинит поля: не число — 0; `hints` строкой — пустой список; неизвестный `tutorial` — нет.
   Открытия построек по-прежнему считает `loadUnlocks`: без поля — открыто то, что заработано, без экранов «Новое!».
2. Ревизия — **не 0**. `legacyRevision` даёт нижнюю оценку числа записей, которые старая версия
   сделала за эту игру: `1 + обучение + подарок + 2 × матчи + подсказки + покупки + подарок дня`.
   Поэтому небольшой облачный снимок с другого устройства не перетрёт накопленное. Проверено: 3 матча и покупки — ревизия 13.
3. Звук берётся из старого ключа `midnight-door-muted` в `settings.muted`, старый ключ удаляется.
4. Сохранение сразу пишется в новой схеме (в safeStorage, если он есть: старые версии писали в обычный `localStorage`).

Снимок **более новой** схемы (`v > 2`, из обновлённой версии игры на другом устройстве) читается как
есть: поля, которых эта версия не знает (на любой глубине — в `meta`, `settings`…), сохраняются и уходят обратно, а не стираются.

## Когда сохраняется

| Событие | Где | critical |
|---|---|---|
| обучение пройдено, пропущено, брошено выходом в меню | `startTutorial` | да |
| игрок до появления обучения отмечен «прошёл» | `boot` | нет |
| итоги матча: счётчик, победы, награда, открытия | `onEnd` | да |
| выход из матча с наградой или после поимки | `onMenu` | да |
| экран «Новое!» подтверждён кнопкой | `openUnlock` → `previewButtons` | нет |
| метка «Новое!» увидена в меню построек | `onBadgeSeen` | нет |
| подсказка показана | `hints.onSeen` | нет |
| началась ночь — усилители списаны | `onNightStart` | нет |
| покупка героя, скина, усилителя | магазин | да |
| выбор героя или скина | магазин | нет |
| подарок дня забран | `openDaily` | да |
| звук включён или выключен | `hud.onToggleMute` (на заставке — запоминается и сохраняется в `boot`) | нет |

Выход живым через паузу до начала ночи ничего не меняет — записи нет.

## Сбои

| Что сломалось | Что будет |
|---|---|
| `/sdk.js` не загрузился (локальная разработка, сеть, блокировщик) | через ≤ 4 с — `localStorage`, игра идёт |
| `getStorage()` упал или завис | `localStorage` |
| `localStorage` запрещён | прогресс в памяти до закрытия вкладки |
| `getPlayer()` упал или завис | локальный прогресс, облако не подключено |
| `getData()` упал или завис | локальный прогресс; облако подключится повтором; до этого в облако не пишем |
| `setData()` отклонён или завис 10 с | локальное не откатывается; облако «грязное»; повтор через 5, 10, 20… до 60 с |
| запись локально бросила (квота) | не падаем; в DEV — сообщение |

Ребёнку ошибки не показываются. В DEV в консоли есть `[Save] …`:
`storage backend`, `local revision N loaded`, `player authorized`, `cloud revision N loaded`,
`selected local/cloud revision N`, `cloud synced revision N`, `Cloud save failed`.
Персональных данных в логах нет. В продакшене лог молчит: всё под `import.meta.env.DEV`.

## Вход в Яндекс и перенос гостевого прогресса

Кнопки «Сохранить прогресс в облаке» пока нет. Когда появится, она вызывает:

```ts
import { signInAndSync } from './platform/save';
await signInAndSync(ysdk, store); // 'local' | 'cloud' | 'none' | 'cancelled'
```

Что происходит:

1. `ysdk.auth.openAuthDialog()`. Закрыл окно — `'cancelled'`, ничего не меняется.
2. Игрок берётся **заново**: `await ysdk.getPlayer()` (≤ 5 с). Старый объект был гостевым.
   Сбой сети — `'failed'`: гостевой прогресс остаётся локально, облако подключится повтором.
3. `store.attachCloud(...)` читает облачный снимок и выбирает новее целиком:
   - гость ревизии 20 (8 матчей) против облака ревизии 10 (4 матча) — остаётся гостевой и уходит в облако;
   - пустой новый браузер против облака ревизии 50 — берётся облачный, заменяется на месте, меню перерисовывается.

В DEV то же самое вручную из консоли: `__save.signIn()`.

## Тесты

[tests/save.test.ts](tests/save.test.ts) — 68 тестов, SDK и хранилища подменены:

- **обучение:** чистый профиль запускает обучение; пройденное и пропущенное переживают перезагрузку; подарок один раз; повтор не сбрасывает профиль; пропуск повтора не превращает «пройдено» в «пропущено»; выход в меню считается пропуском; старый игрок идёт в меню;
- **матчи и монеты:** завершённый матч сохраняется; выход живым не считается; награда и покупка сохраняются, потраченное не возвращается;
- **постройки:** матч 1 открывает тыкву; ожидающий экран «Новое!» переживает перезагрузку; подтверждённый не повторяется; остальные закрыты;
- **герои, усилители, подарок, звук:** покупка и выбор; списанный усилитель не возвращается; подарок дня нельзя забрать дважды;
- **гость и без SDK:** safeStorage, облако не трогается, окно входа не открывается; нет SDK — `localStorage`; нет safeStorage — `localStorage`; нет ничего — память; ошибка записи не роняет; зависший SDK не вешает запуск;
- **облако:** загрузка из облака; пачка — один `setData` с последним снимком; `flush` и пауза 5 с; сбой `setData` — локальное цело, повтор доходит; сбой `getData` — в облако не пишем; отправка при уходе со страницы;
- **выбор:** 7 случаев `chooseSnapshot`; поля не сливаются; битое локальное, битое облако, оба битые; починка полей вместо сброса;
- **вход:** гость новее облака — сохраняется и уходит в облако, игрок запрошен заново; облако новее — замена на месте и `onReplaced`; пустой браузер берёт облако; отмена входа ничего не меняет;
- **миграция:** реальное старое сохранение без потерь (с отдельным ключом звука); самое старое (без `meta` и `unlocks`); перенос из `localStorage` в safeStorage; мигрированное не перетирается маленьким облаком; профиль по умолчанию в облако не уходит;
- **размер:** тяжёлый снимок меньше 2 КБ;
- **гонки облака:** уход со страницы во время отправки; дожим записи без `flush`; изменение во время отправки; два подключения — одно чтение; повторы останавливаются после подключения; позднее облако на новом устройстве; пауза после сбоя; перечитывание облака раз в минуту; сбой `getPlayer` при входе;
- **схема:** поля более новой версии не теряются; ревизия старого сохранения только с `matches`; время не идёт назад.

Тесты «гонок» и «схемы» проверены на коде до правок: первые 9 падали на первой версии, ещё 5 (второй проход проверки) — на второй.

## Известные ограничения

- **Два устройства одновременно.** Выбирается целый снимок, поэтому изменения, сделанные параллельно на двух
  открытых устройствах, не складываются: побеждает большая ревизия, у другого теряются последние действия.
  Для одиночной игры с ребёнком за одним устройством это приемлемо. Перечитывание облака при возврате во вкладку сужает окно.
- **Сбой `getData` в виде пустого ответа.** Если SDK при сбое отдаёт `{}` вместо ошибки, это выглядит как «облака нет».
  Нетронутый профиль всё равно не отправится, но сохранённый локальный уйдёт в облако. По документации сбой — это отклонённый промис; вживую не проверено.
- **Худшая загрузка ~13 с** при плохой сети (4 + 2,5 + 2,5 + 4). Не зависает, но заставка висит дольше.
- **Проверено только на подменах SDK.** Настоящий Яндекс (черновик в консоли разработчика, вход, два браузера) — см. ручную проверку перед выпуском.

Сценарии сохранения построек в [tests/unlocks.test.ts](tests/unlocks.test.ts) тоже идут через `ProgressStore`.
